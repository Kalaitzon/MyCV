# Ioannis Kalaitzidis — Digital CV

An interactive digital CV presented as a retro Windows desktop: draggable
windows, a taskbar, a Start menu and five selectable themes. **Windows 98** is
the default look, from the startup screen through logon and into the
interface; Windows XP and three others are one click away in the Start menu.
Ships in **English** (default) and **Greek**, and adapts to however many
languages you actually upload.

Built with **Vite + React 19 + TypeScript**. No UI framework, no icon
dependency — every icon is inline SVG and every colour is a CSS custom
property, so the whole site ships as a single small JS/CSS bundle.

---

## Quick start

```bash
npm install     # install dependencies
npm run dev     # start the dev server at http://localhost:5173
npm run build   # type-check and build into dist/
npm run preview # serve the production build locally
```

## Project structure

```

  data/
    cv.json                   ALL CV content, EN + EL — generated by import-cv

    themes.ts                 theme metadata (label + swatch)
    config.ts                 resume file path, site title
  components/
    Window.tsx                draggable / resizable window frame
    DesktopIcon.tsx           desktop shortcut
    Taskbar.tsx               taskbar, window buttons, clock, language toggle
    StartMenu.tsx             start menu: programs, language, themes
    BootScreen.tsx            boot + logon screen (98 or XP, follows the theme)
    Icons.tsx                 inline SVG icon set
    content/CvSections.tsx    the contents of each window
  hooks/useWindowManager.ts   open / close / focus / move / resize state
  i18n/                       language context + UI strings
  theme/ThemeContext.tsx      theme selection + persistence
  styles/themes.css           the five colour themes
  index.css                   layout and component styles
scripts/
  import-cv.mjs               AI import from the command line
shared/
  cv-schema.js                extraction schema + prompt, shared by both paths
  providers.js                Gemini / Claude adapters behind one interface
api/
  import-cv.js                serverless endpoint behind the "Update CV" window
public/
  CV_EN.pdf                   downloadable CV, English
  CV_EL.pdf                   downloadable CV, Greek
  favicon.svg
```

### Updating the CV

**Automatically, from a PDF or Word file:**

```bash
npm run import-cv -- --en ./CV_EN.pdf --el ./CV_GR.pdf   # preferred
npm run import-cv -- ./CV_EN.pdf                         # one language only
```

**One document is enough; two unlock the language switcher.** Nothing is ever
translated — the model only ever copies what you wrote.

| You upload | The site publishes | Language switcher |
| --- | --- | --- |
| English only | English | hidden |
| Greek only | Greek | hidden |
| both | both, matched to each other | shown |

The import records this in `meta.availableLanguages` in `cv.json`, and the
switcher in the taskbar and the Start menu disappears when only one language
is published — better a single honest language than a machine translation the
author never wrote. Upload the second document later and the switcher comes
back on the next deploy.

The result is written to `src/data/cv.json` and the site picks it up on the
next build. Each `.pdf` input is also copied to `public/CV_EN.pdf` or
`public/CV_EL.pdf` so the Resume window stays in sync.

Setup, once:

1. Get an AI API key — either works:
   - **Google Gemini** at <https://aistudio.google.com/apikey> — has a free
     tier and needs no card. Note that Google states free-tier content may be
     used to improve its products.
   - **Anthropic Claude** at <https://console.anthropic.com> — paid, roughly
     $0.13 per import, and your data is not used for training.
2. Copy `.env.example` to `.env` and paste the key into `GEMINI_API_KEY` or
   `ANTHROPIC_API_KEY`. `.env` is git-ignored and never leaves your machine.
3. `npm install`

If both keys are present, Gemini is used because it is free. Force a choice
with `CV_PROVIDER=gemini` or `CV_PROVIDER=anthropic`.

If the chosen model is busy (Gemini's free tier returns `503 UNAVAILABLE`
under load) the import retries with exponential backoff, then falls back to
the next model in `FALLBACK_MODELS` rather than giving up. The output reports
which model actually answered.

The Gemini default is `gemini-flash-latest`. Flash rather than Pro is
deliberate: this is structured extraction, not reasoning, so Flash is as
accurate, several times faster (which matters against the 60-second
serverless limit) and far more generous on the free tier. The `-latest` alias
rather than a pinned version is also deliberate — Google keeps retired
versions listed in the models API long after they stop answering requests, so
a pinned name fails one day with a confusing 404.

Accepted formats: `.pdf`, `.docx`, `.txt`, `.md`. Add `--dry-run` to check a
file is readable without spending tokens.

The script also detects which language the document is written in and files a
`.pdf` source as either `public/CV_EN.pdf` or `public/CV_EL.pdf`. The Resume
window links to whichever matches the interface language, so run the import
once with your English CV and once with your Greek one to keep both downloads
current.

**From the site itself — the "Update CV" window:**

Double-click **Update CV** on the desktop (it is in the Start menu too). Enter
the admin password, pick your English CV, your Greek CV, or both, and press
upload — one file is enough, and the table above says what you get. The
password is whatever you set as `ADMIN_PASSWORD` below; there is no default,
and the window only works on the deployed site, since `npm run dev` serves no
`/api` routes. The serverless function at
`api/import-cv.js` does the same extraction as the CLI, then commits the result
straight to this repository, which triggers a Vercel redeploy. About a minute
later every visitor sees the new CV.

This needs four environment variables in **Vercel -> Settings -> Environment
Variables** (never in a committed file):

| Variable | Value |
| --- | --- |
| `GEMINI_API_KEY` **or** `ANTHROPIC_API_KEY` | your AI key (Gemini has a free tier) |
| `ADMIN_PASSWORD` | the password you will type in the site |
| `GITHUB_TOKEN` | fine-grained token, **Contents: Read and write**, this repo only |
| `GITHUB_REPO` | `Kalaitzon/Digital-CV` |

Optional: `GITHUB_BRANCH` (defaults to `main`), `CV_PROVIDER`, `CV_MODEL`.

Security notes, since this endpoint is public:

- The password is compared with `timingSafeEqual`, so response time reveals
  nothing about it. Use a long random one.
- Wrong attempts get a fixed 700 ms delay, and five failures from one IP lock
  that IP out for fifteen minutes.
- Uploads are capped at 3 MB and restricted to `.pdf`, `.docx`, `.txt`, `.md`.
- No secret is ever sent to the browser; the key and token are read only inside
  the function.
- The window has a desktop icon and a Start menu entry on the deployed site.
  Anyone can open it, but without the password it does nothing.

**Local script vs. the window:** the script is better when you want to review
the diff before publishing, and it works with no Vercel configuration at all.
The window is better when you are away from your development machine. Both
write the same `src/data/cv.json` through the same schema in
`shared/cv-schema.js`, so they can never drift apart.

**Manually:** edit `src/data/cv.json` directly. Every field is a `{ en, el }`
pair. Note that the next `import-cv` run overwrites the whole file.

### Adding a new window

1. Write a component in `src/components/content/CvSections.tsx`.
2. Add a title to `src/i18n/strings.ts` (English + Greek).
3. Add one entry to the `APPS` array in `src/data/apps.tsx`.
4. If it needs new data, add the field to `CV_SCHEMA` in
   `shared/cv-schema.js` and to the types in `src/data/cv.ts`. Both the CLI and
   the serverless endpoint pick it up automatically.

The desktop, Start menu and taskbar pick it up automatically.

### Themes

| id            | Name                             |
| ------------- | -------------------------------- |
| `win98`       | Windows 98 — Classic Grey (default) |
| `xp-blue`     | Windows XP — Luna Blue           |
| `xp-silver`   | Windows XP — Silver              |
| `royale-noir` | Royale Noir (dark)               |
| `matrix`      | Hacker Terminal (CRT green)      |

Themes are pure CSS custom properties in `src/styles/themes.css`. To add one,
copy an existing block, change the values and register it in
`src/data/themes.ts`.

Language and theme choices are stored in `localStorage`, so returning visitors
keep their settings.

## Deployment

### Option A — GitHub Pages (already configured)

`.github/workflows/deploy.yml` builds and publishes on every push to `main`.

1. Push the repository to GitHub.
2. Go to **Settings → Pages → Build and deployment** and set
   **Source: GitHub Actions**.
3. Push to `main`. The site appears at
   `https://<username>.github.io/<repo-name>/`.

The workflow sets `BASE_PATH=/<repo-name>/` so assets resolve under the
sub-path automatically.

> The `.github/` folder is **only** used by this option. If you deploy on
> Vercel you can delete it. Note that GitHub's drag-and-drop web uploader skips
> folders whose name starts with a dot — use `git push`, or create the file
> through **Add file → Create new file** and type
> `.github/workflows/deploy.yml` as the filename.

### Option B — Vercel (recommended)

Vercel gives you a shorter URL, automatic HTTPS on a custom domain, preview
deployments for every branch and faster global delivery.

1. Sign in at <https://vercel.com> with your GitHub account.
2. **Add New → Project**, import this repository.
3. Vercel detects Vite automatically — keep the defaults
   (build `npm run build`, output `dist`) and click **Deploy**.
4. Optionally add a custom domain under **Settings → Domains**.

`vercel.json` is included with the framework preset and long-lived cache
headers for hashed assets. When deploying to Vercel the site is served from the
domain root, so no `BASE_PATH` is needed.

## Accessibility & compatibility

- Every interactive element is a real `<button>` or `<a>`, so keyboard
  navigation and screen readers work.
- The boot animation is skipped automatically for visitors with
  `prefers-reduced-motion`.
- Windows are auto-maximized on small screens; the layout is responsive down to
  phone widths.
- Drag and resize use Pointer Events, so touch works the same as mouse.
